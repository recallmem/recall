Discord and Slack bots

For bots that live in a busy Discord server or Slack workspace, where hundreds of members talk in the same channels. Recall keeps every member apart, remembers each one across channels and weeks, and keeps what someone told the bot in private out of its public replies.

What memory adds

Without memory, the bot sees the message that mentions it and perhaps the last few lines of the channel. With it, the bot knows who is asking:

Without memoryWith Recall
"@bot any tips for the level 12 boss?"Generic tips for every class."As a frost mage, swap to a fire staff for this fight: the boss is immune to frost."
Two members both called AlexThe bot mixes them up.Each is a peer keyed by user id; their memories never meet.
A member tells the bot in a DM that they may leave the raid teamA bot with one shared history may repeat it in #general.The DM feeds only that member's own memory, which the bot reads in that DM and nowhere else.

Recall is memory, not the bot: your model writes the replies and your bot code talks to Discord or Slack. Recall has no Discord or Slack integration of its own; the bot calls the SDK.

Build it

Install the SDK (npm install @recall-memory/sdk or pip install recall-mem) and set RECALL_API_KEY. Create the bot peer and turn off learning from it before its first line is stored, then a session per channel in which the bot observes the others.

Busy channels: batch, and only read when asked. Storing every message as it arrives is a request per message, and a busy server soon meets the rate limit. Buffer what nobody addressed to the bot and store it every few seconds in one request (up to 100 messages; the SDKs split larger batches). When someone mentions the bot, turn stores their message and returns the context for the reply in one request of a fraction of a second.

DMs stay private. In a DM the bot reads the member's own memory, which includes what they said in public. In public it reads only its own view, which was never told what was said in a DM.

Ask about a member. For a /memory command or a moderator tool, ask the bot's view of one member in plain language. That is a model call of a few seconds, so keep it out of the reply path.

Forget on request.

Wiring it to discord.js or Slack Bolt

The platform code stays small. A sketch for discord.js, with one Recall client per server and the calls from above; yourModel stands for your own model call:

const clients = new Map(); // guild id -> Recall client for that server's workspace
async function recallFor(guildId) {
  if (!clients.has(guildId)) {
    const recall = new Recall({ workspaceId: `discord-${guildId}` });
    await recall.peer("bot").setConfiguration({ observeMe: false });
    clients.set(guildId, recall);
  }
  return clients.get(guildId);
}
const pending = new Map(); // channel id -> messages not stored yet

client.on("messageCreate", async (msg) => {
  if (msg.author.bot || !msg.guild) return;
  const recall = await recallFor(msg.guild.id);
  const author = recall.peer(`discord-${msg.author.id}`);
  const waiting = pending.get(msg.channelId) ?? [];
  pending.set(msg.channelId, waiting);
  waiting.push(author.message(msg.content, { createdAt: msg.createdAt }));
  if (!msg.mentions.has(client.user)) return; // a timer flushes `waiting` with addMessages

  const channel = recall.session(`ch-${msg.channelId}`, {
    peers: { bot: { observeOthers: true } },
  });
  const { context } = await channel.turn(waiting.splice(0), {
    peerTarget: author,
    peerPerspective: "bot",
    tokens: 1500,
  });
  const reply = await yourModel(context.toOpenAI("bot"));
  await msg.reply(reply);
  await channel.addMessages([recall.peer("bot").message(reply)]);
});

With Slack Bolt the same calls go in app.message (buffer) and app.event("app_mention") (turn); peer ids are slack- plus the user id, and the workspace is named after the Slack team id. Both platforms expect a slash command to be acknowledged within a few seconds, so acknowledge first and then ask.

Settings that matter

SettingUse
observeMe: false on the botRecall learns about members only. Set it before the bot's first line is stored.
observeOthers: true for the bot in public channelsBuilds the bot's own view of each member. Only the bot needs it: a session allows at most 10 members with it, so never give it to members.
peerPerspective: bot in public channelsRead a member through the bot's public view, so nothing from a DM comes up.
tokensThe context budget. 1,000 to 2,000 holds a busy channel's recent lines, a summary and what is known about the member.
Message createdAtPass the platform's timestamp when you flush a buffer, so each message keeps the time it was written.
configuration: { reasoning: { enabled: false } } on a sessionFor channels worth keeping as history but not learning from, such as a memes channel. Their messages count only what Recall reads of them.

Cost and speed

Measured from Europe against the hosted API (Frankfurt), October 2026: a turn or context call took 0.3 to 0.7 seconds, and a question at minimal or low 2 to 4.5 seconds. Learning runs in the background and never holds up a reply. When you go over the rate limit (counted per API key), Recall answers 429 with Retry-After; the SDKs wait that long and retry, but batching is what keeps you under it.

Context and search are included. You pay for learning, $1.75 per million message tokens with every message counting as at least 50, and for questions. Members who only read cost nothing. An active member who posts 200 short messages a month, gets 40 replies from the bot of about 80 tokens, and runs /memory 5 times:

Privacy and forgetting

Members do not expect a bot to remember them unless they are told. Pin a notice in the channels the bot reads, say it in the bot's profile, and give members two commands: /memory to see what the bot knows about them, and /forget to erase it. When a member asks, or leaves the server if your notice says so, delete erases their messages and every fact about them or from their view; other members' messages and facts about others that merely mention them stay. A member who never spoke answers 404: there is nothing to forget.

Do not store what the bot does not need: skip channels it is not used in, and never record moderators' private channels. Many Discord communities include teenagers; read Privacy, consent and forgetting before you build profiles of them. Recall stores data in Frankfurt; text is processed by AI models from Anthropic in the US, and never used for training. See the DPA and Forget a person.

Pitfalls

  • Display names as ids. Names change and repeat, and memories follow the name to the wrong person. Use the platform's user id.
  • One request per message. A busy channel then hits 429. Batch, and call turn only when the bot is addressed.
  • Public replies without peerPerspective. The member's own memory includes their DMs, which can then surface in front of everyone.
  • One workspace for every server. What a member said in one community follows them into another. Use a workspace per server.
  • observeOthers for members. A session allows at most 10, and members do not need their own view. Give it to the bot only.
  • Asking on every message. A question takes seconds and costs per call. Replies need context, not questions.
