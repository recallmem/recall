Coding agents

For developers who want Claude Code, Codex or an agent of their own to remember how they work, what a repository's rules are and what was decided last month. Install an integration in a few minutes, or add memory to your own agent with the SDK.

What memory adds

Without memory, every coding session starts from the same blank page and you repeat your preferences in each one. With it, the agent starts where the last session ended:

Without memoryWith Recall
Monday, a new sessionThe agent runs npm install and you correct it, again.It already knows you use pnpm, want small commits and write the test first.
A task that needs a schema changeIt edits the generated migration by hand.It starts with the repository rule: migrations are generated, never edited.
"Why is refund_reason nullable?"Nobody remembers; someone searches chat history.It answers from the session where that was decided: the backfill comes later.

Recall is memory, not the agent. It does not read your repository, index files or run tools; it stores what you and the agent said and learns from it. Code search stays with your agent.

Build it

Claude Code, Codex and other agents

Each integration recalls (adds your peer card and the facts Recall learned about you to the agent's context), records (stores your prompts and the agent's final replies) and, where the agent supports it, adds Recall's MCP tools so the agent can look things up and correct memory. The agent is a peer Recall does not observe (claude, codex), so facts are learned about you.

Claude Code. Install the plugin, and enter your API key when Claude Code asks for it (it is kept in your system's credential store):

/plugin marketplace add recallmem/recall-plugin
/plugin install recall-memory@recall

Set the workspace and your peer id under /plugin → recall-memory → Configure, or with RECALL_WORKSPACE_ID and RECALL_PEER_ID. Then run /recall-memory:status to check the connection. Each Claude session is recorded in a Recall session named cc-<session id>.

Codex. codex plugin marketplace add recallmem/recall-plugin and codex plugin add recall-memory@recall, or the installer; pick one, because both together handle every turn twice. Codex skips new hooks until you trust them, so run /hooks once. The key comes from RECALL_API_KEY or ~/.recall/config.json (see connect to your server).

A team on the integrations. Everyone uses the same workspace and their own stable peer id. Each developer's memory is their own; rules they ask the agent to remember are saved as facts about them. For rules the whole team shares, write them to a repository peer as shown below.

Any MCP client. Point it at https://api.recallmem.dev/mcp. Cursor, VS Code and Claude Code (claude mcp add --transport http recall https://api.recallmem.dev/mcp, then /mcp → Authenticate) sign in with your email; no key is copied. Through MCP the model decides when to look things up. With Remember automatically on (the default for a connected app; change it under API keys → Connected apps) it also saves lasting facts you share without being asked. See Add Recall as a connector.

What the plugins send: your prompts and the agent's final replies, each cut to 24,000 characters, to the Recall server you configured. Tool calls and their output, including the files the agent reads, are not sent. RECALL_RECORD=false stops recording and keeps lookup; RECALL_ENABLED=false under env in a project's .claude/settings.json switches Recall off for that project.

Your own agent

Install the SDK (npm install @recall-memory/sdk or pip install recall-mem) and set RECALL_API_KEY. Create the peers and a session per coding session. Set observeMe: false before the agent's first message is stored.

Rules you know for sure: write them. Conclusions are facts you state directly. They are searchable at once, without waiting for background learning, and every developer's agent reads the same ones.

Session start: read, focused on the task. searchQuery pulls the facts that matter for this task into the prompt instead of the most frequent ones. Both are reads, not questions: no answer is generated, so they are fast and included in the price. Run them in parallel.

After each turn: record the conversation, not the work. The developer's prompt and the agent's final answer are what Recall learns from. Build logs, diffs and file contents cost tokens and teach it nothing about the developer, and they are where secrets hide.

Past decisions: ask the repository. A question with scope reads only the sessions filed under that repository. It is one model call of a few seconds, so ask when the agent needs it, not on every turn.

Rules change, people leave.

Cost and speed

Measured from Europe against the hosted API (Frankfurt), October 2026: a context read took 0.3 to 0.7 seconds, so memory at session start adds well under a second. A question at low took 2 to 4.5 seconds. Learning runs in the background and never holds up a turn.

Context, search and storage are included. You pay for learning, $1.75 per million message tokens with every message counting as at least 50, and for questions. A developer who works 20 days a month, with 30 prompts a day of about 100 tokens, the agent's 30 replies (long, but read only as context, at most 200 tokens each), and 40 questions about past decisions:

Privacy and forgetting

Prompts carry more than preferences: pasted errors with connection strings, customer data from a bug report, code under NDA. Tell your team what the agent records, switch recording off for repositories that must not leave your machines, and never record tool output or file contents from your own agent. Recall stores data in Frankfurt; text is processed by AI model providers in the US through OpenRouter, restricted to providers that do not collect it, and is never used to train models. If you work on client code, check that your contract allows a processor; see the DPA.

To remove one wrong or outdated fact, ask the agent to forget it (the MCP tools include delete_conclusion) or delete it by id. When a developer leaves, dev.delete() erases their messages and every fact about them or from their view; facts about other peers that merely mention them stay. See Forget a person, Export your data and Privacy, consent and forgetting.

Pitfalls

  • Secrets in prompts. A pasted .env or token is recorded with the prompt. Redact before you record, and use RECALL_RECORD=false for repositories you cannot risk.
  • One workspace for several clients. What the agent learned in one client's code then surfaces in another's. Use a workspace per client, each with its own key.
  • Team rules said only in passing. A rule mentioned once in a chat is learned as a fact about the developer who said it. Write rules the whole team follows to the repository's peer.
  • Recording tool output. Logs and file dumps cost tokens and teach nothing about how anyone works. Record the prompt and the final answer.
  • Both Codex routes installed. The plugin and the installer each handle every turn, so everything is recorded twice. Pick one.
  • Expecting it to know the code. Recall remembers conversations, not files. The agent still needs its own code search.
