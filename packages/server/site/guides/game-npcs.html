Game NPCs

Characters that remember the player across play sessions, each from their own point of view: the blacksmith remembers the hammer you lost, the innkeeper only knows what reached his ears. Recall stores the scenes, learns what each NPC saw, and hands your dialogue model the right memory in a few hundred milliseconds.

What memory adds

Without memory, every conversation with an NPC starts from the script. With it, what the player did and said becomes part of the world:

Without memoryWith Recall
Day 3, at the forgeThe player loses Mira's hammer and promises her 30 gold by the harvest festival.
Day 9, back at the forge"Welcome, traveller! Need a blade?""Back again. The festival is in two days, and I still don't see thirty gold."
Day 9, at the innTomas has never heard of it.Only if your story let the rumour travel: Tomas knows what you told him, nothing more.

Recall does not write the lines. Your game's own model does, as it does now; Recall gives it what this NPC knows about this player, and learns from what was said.

How to model it

In your gameIn RecallWhy
A save game (or one player's world)Workspace, e.g. save-7f3aMemories of different saves never mix, and a new game is one delete.
The playerPeer playerRecall learns about the player from everything they say.
Each NPCPeer npc-mira, npc-tomas, with observeMe: falseYou write NPC personalities yourself, so Recall need not learn about them; their lines cost less.
A scene or conversationSession, e.g. forge-day-3The NPCs in a session are the ones who witnessed it.
What an NPC knowsThe NPC's view of the player: observeOthers: true in that NPC's sessionsMira's view is built only from scenes Mira was in.

Multiplayer works the same way: one peer per player, and each NPC keeps a separate view of each player it met. For a shared world, use one workspace per server or shard instead of per save.

Build it

Install the SDK (npm install @recall-memory/sdk or pip install recall-mem) and set RECALL_API_KEY. Create the save's peers and a session per scene; nothing is sent until the first call.

Every line of dialogue: one request. turn stores the player's line and returns the context for the reply in the same round trip: the scene so far, a summary of older turns, and what Mira has learned about the player. peerPerspective is what keeps her view her own. It uses no model, so it is fast and included in the price.

Game logic: ask. For decisions (does Mira refuse to sell? does the debt quest unlock?), ask the NPC's memory in plain language. That is one model call of a few seconds, so call it when a quest step or a scene starts, not every frame. Ask for JSON with responseFormat when your code needs a field rather than a sentence.

Rumours spread when your story says so. NPCs who were not there know nothing. To pass news on, write a fact into the listener's view yourself. That keeps gossip under your control instead of leaking between characters.

Unity, Unreal and Godot

There is no engine SDK; the REST API is two calls. Do not put your API key in the game build, where players can extract it: call Recall from your game server, or mint each player a key scoped to their own save with POST /v3/keys, so a leaked key reaches no one else's memory (set a monthly cap under Billing too). The turn call from C#:

// POST /v3/workspaces/{save}/sessions/{scene}/turn
var body = @"{
  ""messages"": [{ ""peer_id"": ""player"", ""content"": ""I lost your hammer in the river."" }],
  ""context"": { ""tokens"": 2000, ""peer_target"": ""player"", ""peer_perspective"": ""npc-mira"" }
}";
using var req = new HttpRequestMessage(HttpMethod.Post,
    $"https://api.recallmem.dev/v3/workspaces/{save}/sessions/{scene}/turn");
req.Headers.Authorization = new AuthenticationHeaderValue("Bearer", apiKey);
req.Content = new StringContent(body, Encoding.UTF8, "application/json");
var res = await http.SendAsync(req);   // { "messages": [...], "context": { ... } }

Set up each scene once, before its first turn: POST /v3/workspaces/{save}/sessions with {"id": "forge-day-3", "peers": {"player": {}, "npc-mira": {"observe_others": true}}}. It is get-or-create, so sending it again is harmless. See the REST API.

Settings that matter

SettingUse
observeOthers: true per NPC, per sessionThe NPC builds its own view of the others in that scene. Leave it off for NPCs who should not remember.
peerPerspectiveRead the player through that NPC's eyes. Without it you get Recall's overall view of the player, which includes things the NPC never saw.
observeMe: false on NPCsRecall does not learn about the NPC from its own lines. Use it whenever your game, not the conversation, defines who the NPC is.
tokensThe context budget for the dialogue model, 1,000 to 4,000 is plenty for a scene. Older turns become a summary.
reasoningLevel: "minimal"For game logic questions: the cheapest and fastest level. See Reasoning levels and models.
Message createdAtRecall dates what it learns by when a message was written. If your world has its own clock, map game days onto dates and pass them, so "by the festival" is reckoned in game time.

Cost and speed

Measured from Europe against the hosted API (Frankfurt), October 2026: a turn or context call took 0.3 to 0.7 seconds, a question at minimal or low 2 to 4.5 seconds. Learning happens in the background and does not hold up the call.

Context and search are included. You pay for learning, $1.75 per million message tokens with every message counting as at least 50, and for questions. A player who plays two hours a week, with 200 lines of their own and 200 NPC lines of about 30 tokens, and 20 game-logic questions:

Privacy and forgetting

Players type freely into chat-driven games, including things that are not about the game. Say in your privacy notice that conversations with characters are stored to give them memory, and let players reset it. Deleting the save's workspace removes everything in it; player.delete() forgets one player in a shared world, including every NPC's view of them. Games for children need more care: see Privacy, consent and forgetting.

Pitfalls

  • One workspace for all saves. Memories from a deleted save then haunt the new one. Use a workspace per save or per world.
  • Asking in the frame loop. Questions take seconds. Read context for dialogue; ask only for game logic, ahead of time.
  • Reading without peerPerspective. Every NPC then knows everything the player ever said to anyone.
  • NPC ids that change between builds. Memory belongs to the id: keep npc-mira stable even if her display name changes.
  • Expecting the NPC's lines to be written for you. Recall is memory, not the dialogue model; bring your own model and persona prompt.
