Voice agents

For phone lines and voice assistants: an agent that knows who is calling and what happened last time, without adding silence to the call. You read the caller's memory while the call connects, store each utterance in one fast request that runs next to your model, and leave anything that takes seconds until after the hang-up.

What memory adds

Without memory, every call starts with "how can I help?" and the same questions. With it, the agent knows the story so far:

Without memoryWith Recall
Monday's callThe caller reports that the internet drops out every evening. The agent resets the line and promises to check it again on Friday.
Friday, same caller, verified"What is the reason for your call today?""Is this about the evening drop-outs? We said we would check your line today."
A month later"Which router do you have?""Is it still the white router we sent in August? And shall I call you back after six, like last time?"

Recall does not hear or speak. Your speech-to-text, model and text-to-speech do; Recall stores the transcript and gives your model the caller's memory.

How to model it

On your lineIn RecallWhy
Your phone line or voice productWorkspace, e.g. support-lineOne per product and environment, so test calls never mix with real callers.
The callerPeer: your account id (cust-1042) once verified, otherwise caller- and a keyed hash of the numberOne stable id per person, and never the raw number.
Your voice agentPeer voice-agent, with observeMe: falseRecall does not learn from the agent's lines, only reads them as context, so they cost less.
A callSession, e.g. call-7f3e9a2c, from your telephony provider's call idOne transcript per call, its own running summary, and one place to delete it.
What the caller said on earlier callsThe peer card and facts, returned with the contextReady for the first prompt, before the caller says a word.

Why not the phone number? Ids show up in request paths, logs, exports and the dashboard, and cannot be renamed. A plain SHA-256 of a number protects nothing, because every possible number can be hashed and compared. A keyed hash (an HMAC with a secret only your server holds) cannot be reversed without the key, and the same number always gives the same id, so you can still find a caller to delete them. A number is still not a person, though: numbers change hands and a household can share one line. Once a caller is verified against your accounts, key memory by your account id and keep the number-to-account mapping in your own system; use the hashed number only for callers you cannot identify.

Build it

Install the SDK (npm install @recall-memory/sdk or pip install recall-mem) and set RECALL_API_KEY on the server that handles your call events. Configure the agent once at startup; per call you only need two handles, which make no request.

Before the first word: read the caller's memory. As soon as the call connects, while your greeting plays, read the session context with the caller as peerTarget. It is one request (a context call measured 0.3 to 0.7 seconds) and works before the session exists, so a first-time caller gets empty context rather than an error. The result holds the caller's peer card and facts, ready as system messages. Until the caller is verified, keep personal details from it out of what the agent says.

Each utterance: one request, off the critical path. When speech-to-text gives you the final transcript of an utterance, send it with turn, together with the agent's previous line, so one request stores both. A turn measured 0.3 to 0.7 seconds, which is too long to add to every reply. Your model does not need to wait for it: it already has the memory from the start of the call and the call so far, so start the model call and the turn together. Use the context the turn returns for the next utterance; on a long call it replaces older turns with a summary, so the prompt stays within tokens.

Questions wait until the call is over. chat took 2 to 4.5 seconds at minimal or low, which is dead air on a phone line. Never call it inside a turn. Ask before the call when you can (an outbound call you are about to place), or after it, for your CRM or to prepare the next call. If a question must inform this call, start it in the background when the call connects and use the answer only if it arrives in time.

After the hang-up: the summary and anything slow. Store the agent's last line. Recall keeps a running summary of each session, written every 20 messages by default (at least 10, set with messagesPerShortSummary), and summaries() returns it; a short call may not have one. A queue.empty webhook tells your server when learning for the call has finished, so you do not need to poll. For a note on every call, short ones included, ask a question as below ($0.005 at low), or have your own model write it from the transcript you already hold.

A caller asks to be forgotten. Verify them, derive the id from their number with the same key, delete their calls (the agent's lines quote them), then the caller. delete() erases their messages, every fact and card about them, and cached answers.

Other languages and voice platforms

Recall has no telephony SDK; call it from whatever handles your call events. Over REST, the call start and each utterance are one request each. The context read:

curl -G $RECALL_URL/v3/workspaces/support-line/sessions/call-7f3e9a2c/context \
  -d tokens=1500 -d peer_target=cust-1042 \
  -H "Authorization: Bearer $RECALL_API_KEY"

Each utterance, with the agent's previous line. The Idempotency-Key header makes a retry safe; the speech-to-text segment id is a good value:

curl $RECALL_URL/v3/workspaces/support-line/sessions/call-7f3e9a2c/turn \
  -H "Authorization: Bearer $RECALL_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: call-7f3e9a2c-utt-7" \
  -d '{"messages":[
        {"peer_id":"voice-agent","content":"Thanks for calling. How can I help?"},
        {"peer_id":"cust-1042","content":"Hi, me again. The internet keeps dropping out."}
      ],
      "context":{"tokens":1500,"peer_target":"cust-1042"}}'

The answer is {"messages": [...], "context": {...}}: the stored messages and the context for the next prompt. The first turn creates the session and the caller. See the REST API.

Cost and speed

Measured from Europe against the hosted API (Frankfurt), October 2026: a turn or context call took 0.3 to 0.7 seconds, a question at minimal or low 2 to 4.5 seconds. Learning happens in the background and never holds up a call. Speech-to-text, your model and text-to-speech already sit between the caller and the reply, so keep Recall beside that path, not on it: context while the call connects, each turn next to your model, questions after the hang-up.

Context reads and turns are included; you pay for learning from the messages a turn stores, $1.75 per million message tokens with every message counting as at least 50, and for questions. A caller who calls four times a month, with 30 short utterances and 30 agent lines of about 30 tokens per call, and one question after each call:

Privacy and forgetting

This is practical guidance, not legal advice. See Privacy, consent and forgetting for the general picture.

  • Tell callers, and get consent where it is required. Say at the start that the call is transcribed and that the assistant remembers earlier calls. The rules on recording and transcribing calls differ between countries, and in some countries between states; some require every party's consent. Recall stores the text you send, never audio.
  • Caller ID is not identity. Numbers can be spoofed. Verify the caller, with a code, account details or a call back, before the agent repeats anything personal from memory.
  • Keep secrets out of the transcript. Redact card numbers, PINs, one-time codes and answers to security questions before an utterance reaches Recall.
  • Say where the data goes. Transcripts are stored in the EU (Frankfurt) and processed by AI model providers in the US through OpenRouter, restricted to providers that do not collect the data; they are not used to train models.
  • Forget on request. Delete the caller and their calls as above. Facts about other people that merely mention them stay; delete those with DELETE …/conclusions/{id} if needed (Forget a person).

Recall's own terms are in the privacy policy and the DPA.

Pitfalls

  • Asking during the call. A question takes seconds, which is silence on a phone line. Read context during the call; ask before or after it.
  • Recall in series with your model. Waiting for each turn before you start your model adds its 0.3 to 0.7 seconds to every reply. Start both together.
  • The raw number as id. It ends up in logs and URLs, and memory follows the number to its next owner. Use your account id, or a keyed hash for callers you cannot identify.
  • Trusting caller ID. Anyone can show someone else's number. Verify before the agent uses personal memory.
  • Expecting a summary after every call. The running summary is written every 20 messages by default, so short calls have none. For call notes, ask a question or use your own model.
  • Expecting Recall to listen. It works on text. Bring your own speech-to-text, model and voice.
